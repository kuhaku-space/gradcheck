# 技術選定

日付: 2026-07-07
ステータス: 採用

## 背景・要求

KOAN からダウンロードした成績 CSV（Shift_JIS エンコード）を読み込み、
大阪大学大学院情報科学研究科 博士前期課程（コンピュータサイエンス専攻）の
修了要件を満たしているかを判定・可視化する Web アプリを作る。

判定に効く要求は次の 3 点。

1. **プライバシー**: 成績・学籍番号という機微情報を扱う。外部サーバに
   送信しない構成が強く望ましい。
2. **運用コスト**: 個人〜研究室規模の利用。サーバの維持・監視はしたくない。
3. **判定ロジックの信頼性**: 修了判定は間違えると実害がある。ロジックを
   UI から分離して単体テスト可能にする。

## 決定

**クライアントサイド完結の SPA（静的サイト）** として構築する。

| 項目                 | 採用                         | 理由                                                                                                                                                                              |
| -------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 実行形態             | ブラウザ内完結 SPA           | CSV をサーバに送らない。成績データがネットワークに一切出ない                                                                                                                      |
| ビルドツール         | Vite                         | 事実上の標準。設定が薄く、静的出力で GitHub Pages 等にそのまま置ける                                                                                                              |
| UI フレームワーク    | React 19 + TypeScript        | 判定結果（要件ごとの充足/不足）の宣言的レンダリングに向く。型で CSV レコード・判定結果の構造を固定できる                                                                          |
| CSV パース           | Papa Parse                   | クォート・埋め込みカンマ・BOM を正しく扱う定番。自前実装は引用符処理でバグりやすい                                                                                                |
| 文字コード           | ブラウザ標準 `TextDecoder`   | `shift_jis` は Encoding Standard で必須サポート。追加依存なしで CP932 をデコードできる。UTF-8 (fatal) → 失敗時 Shift_JIS の自動判別                                               |
| テスト               | Vitest                       | Vite と同一設定で動く。判定ロジック（純粋関数）の単体テストに使用                                                                                                                 |
| スタイリング         | 素の CSS                     | 画面は実質 1 枚。Tailwind 等を入れるほどの規模ではなく、依存を最小に保つ                                                                                                          |
| パッケージマネージャ | pnpm（mise で管理）          | content-addressable store によりインストールが速くディスク効率が良い。`packageManager` フィールドと `mise.toml` でバージョンを固定                                                |
| デプロイ             | Dokku（Dockerfile デプロイ） | 自前サーバで `git push` のみで公開できる。マルチステージビルドで nginx が `dist/` を配信し、実行イメージに Node.js・成績データを含めない（手順は [deployment.md](deployment.md)） |

## 検討した代替案

### 実行形態

- **サーバサイド判定（Flask / FastAPI / Express など）** — 不採用。
  成績 CSV をサーバに送ることになりプライバシー要件に反する。
  ホスティングの維持コストも発生する。判定はただの集計であり
  サーバ計算力は不要。
- **CLI ツール** — 不採用。ユーザーの「Web アプリ」という要求に反する。
  非エンジニアの学生が使う想定ではブラウザ UI が適切。

### UI フレームワーク

- **Vue / Svelte** — 機能的には十分だが、React が最も普及しており
  保守者を選ばない。規模が小さいのでどれでも成立するため、
  エコシステムの大きさで React を選択。
- **バニラ JS** — 依存は最小になるが、要件ごとの判定結果テーブルや
  科目一覧の描画で DOM 操作コードが膨らみ、かえって保守性が下がる。

### CSV パース・文字コード

- **自前パーサ** — 不採用。KOAN の CSV はダブルクォート囲み・末尾ゴミ列
  （行末カンマ + タブ）があり、エッジケースを踏みやすい。
- **encoding.js での判別** — 不採用。`TextDecoder('shift_jis')` で足りる。
  UTF-8 判定は `TextDecoder('utf-8', { fatal: true })` の例外で行えるため
  追加ライブラリ不要。

### デプロイ

- **GitHub Pages / Netlify 等の静的ホスティング** — 静的サイトなので技術的には
  十分だが、自前サーバでの運用（アクセス制御やドメインの自由度）を優先して
  Dokku を採用。`base: './'` は維持しているため、静的ホスティングへの
  切り替えはいつでも可能。
- **Dokku buildpack（nginx/static buildpack）** — 不採用。Dockerfile の方が
  ビルド環境（Node・pnpm のバージョン）を完全に固定でき、ローカルでも
  同一イメージを検証できる。

## 帰結

- 成績データはブラウザメモリ内でのみ処理され、ネットワークに出ない。
- デプロイは `git push dokku main` のみ。Dokku が Dockerfile を検出して
  ビルドし、nginx が静的ファイルを配信する（手順は [deployment.md](deployment.md)）。
- 判定ロジックは `src/lib/` の純粋関数として実装し、Vitest でテストする。
  修了要件の改定時は `src/lib/rules.ts` の定数を更新すればよい。
